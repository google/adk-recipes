# Python Recipes

Everything Python-specific in one place. Universal requirements
live in [anatomy](../anatomy.md).

## Package layout

Every Python recipe uses this shape:

```text
contrib/python/my-recipe/
  Dockerfile                # required for contrib/ (serves on port 8080)
  pyproject.toml            # project spec + deps
  uv.lock                   # pinned deps
  .env.example              # env vars the recipe reads
  manifest.yaml             # recipe metadata (see anatomy)
  README.md                 # description, setup, run
  app/
    __init__.py             # runs load_dotenv(), then imports agent
    agent.py                # your agent code
    fast_api_app.py         # serving entrypoint (generated by make-python-recipe-deployable)
    app_utils/              # A2A and serving adapters (generated by make-python-recipe-deployable)
  tests/
    test_runnability.py     # import smoke test
```

**Name the Python package `app`.** The root Ruff/isort configuration marks
`app` as first-party; other package names produce wrong import ordering.

**Minimum Python:** 3.11.

## The fast path

**New recipe:**

```text
"scaffold a new Python recipe at contrib/python/my-recipe"
# ... write your agent in app/agent.py ...
"prepare the python recipe contrib/python/my-recipe"
"make contrib/python/my-recipe deployable"
```

**Updating a recipe:**

```text
"prepare the python recipe contrib/python/my-recipe"
```

`prepare-python-recipe` is safe to re-run and won't overwrite
your `.env.example` or hand-written Python code.

Full skill reference:
[skills catalog](../skills-catalog.md#python-skills).

> **Model selection:** Prefer a current model such as `gemini-3.7-flash` via
> `MODEL_NAME` in `.env.example`. Avoid deprecated `gemini-2.0-flash` and
> `gemini-2.5-flash`.

## Copy-paste starters

The `scaffold-python-recipe` and `make-python-recipe-deployable` repo skills
create these for you. Use them by hand if you're setting up a recipe manually.

### `pyproject.toml`

```toml
[project]
name = "my-recipe"           # see "Project name" below
version = "0.1.0"
requires-python = ">=3.11"
dependencies = [
    "google-adk[gcp,otel-gcp]>=2.6.0,<3.0.0",
    "python-dotenv>=1.0.0,<2.0.0",
    "a2a-sdk[http-server]>=1.0,<2",
    "aiohttp>=3.13.4",
    "gcsfs>=2024.11.0",
    "opentelemetry-resourcedetector-gcp<=1.12.0a0",
    "google-cloud-aiplatform[agent-engines]>=1.156.0,<2.0.0",
]

[dependency-groups]
dev = [
    "pytest>=8.3.5",
]

[tool.hatch.build.targets.wheel]
packages = ["app"]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[[tool.uv.index]]
url = "https://pypi.org/simple/"
default = true
```

**Project name.** `[project].name` is derived from where the
recipe lives:

| Location | `[project].name` | Example |
| --- | --- | --- |
| `core/<language>/<recipe>` | the folder name | `deep-search` |
| `contrib/<language>/<recipe>` | the folder name | `financial-advisor` |
| `plugins/<vertical>/<solution>` | `<vertical>-<solution>` | `retail-product-search` |

Plugins prefix `[project].name` with the vertical (`<vertical>-<solution>`)
because the folder name alone is not unique across verticals —
`plugins/retail/product-search` and `plugins/grocery/product-search` would
otherwise both claim the distribution name `product-search`. It also keeps the
package name aligned with the plugin's `SKILL.md` `name:` field.

Optional: add `description` if you want it in your `pyproject.toml`
— it must match `manifest.description` exactly. Do NOT add
`[tool.ruff]` or a local `ruff.toml` (Ruff config is
centralized at the repo root).

### `Dockerfile` (`contrib/`)

`make-python-recipe-deployable` generates this `Dockerfile` along with
`app/fast_api_app.py` and `app/app_utils/`. If you build the container
manually without `app/fast_api_app.py`, use
`CMD ["uv", "run", "adk", "api_server", "--host", "0.0.0.0", "--port", "8080", "."]`.

```dockerfile
FROM python:3.11-slim

RUN pip install --no-cache-dir uv==0.8.13

WORKDIR /code

COPY ./pyproject.toml ./README.md ./uv.lock* ./
COPY ./app ./app
COPY ./.env.example ./.env

RUN uv sync --frozen

RUN useradd --create-home --uid 1000 appuser && \
    chown -R appuser:appuser /code /home/appuser

USER appuser

EXPOSE 8080

CMD ["uv", "run", "uvicorn", "app.fast_api_app:app", "--host", "0.0.0.0", "--port", "8080"]
```

### `.env.example`

```dotenv
GOOGLE_CLOUD_PROJECT=your-project-id
GOOGLE_CLOUD_LOCATION=us-central1
MODEL_NAME=gemini-3.7-flash
```

Every env var your code reads must appear here. Read model
names from `MODEL_NAME` — never hardcode a model literal in
source. Avoid deprecated `gemini-2.0-flash` and `gemini-2.5-flash`.

### `app/__init__.py`

```python
from dotenv import load_dotenv

load_dotenv()

from . import agent  # noqa: E402
```

Call `load_dotenv()` here, not in `agent.py`. `__init__.py`
runs first when the package is imported, so `.env` loads
before any env-var reads at agent-import time. The
`# noqa: E402` tells Ruff the late import is intentional.

### `tests/test_runnability.py`

```python
"""Runnability tests for the recipe."""


def test_agent_runnability() -> None:
    """Verify agent.py imports and defines root_agent."""
    import app.agent

    assert app.agent.root_agent is not None
```

This is the bare minimum; extend it with mocks if your recipe runs external
initialization at import time. The test imports `app.agent` and asserts that
`root_agent is not None`.

## Integration tests

Tests that hit real external resources (Gemini, BigQuery,
third-party APIs). CI skips them for speed and credentials —
run them locally before opening a PR.

**Excluded from CI:**

| Pattern | Excluded |
|---|---|
| `tests/integration/` | Everything under this directory |
| `**/test_integration.py` | Files with this exact name, any depth |

**Adding one:** create a file matching either pattern, write
it with real API calls, document credential setup in the
recipe's `README.md`. Run locally:

```bash
cd contrib/python/my-recipe
uv run pytest tests/integration    # integration only
uv run pytest                      # full suite
```

## Local commands

```bash
# Structural checks (all validators at once)
uv run validate contrib/python/my-recipe
# Or individual: manifest / structure / readme / placement
uv run validate readme contrib/python/my-recipe

# Format and lint
uv run ruff format contrib/python/my-recipe
uv run ruff check contrib/python/my-recipe

# Tests (mirrors CI — integration excluded)
cd contrib/python/my-recipe
uv run pytest --ignore=tests/integration \
  --ignore-glob="**/test_integration.py"
```
