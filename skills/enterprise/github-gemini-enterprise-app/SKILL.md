# GitHub Gemini Enterprise App

Guide the user through configuring this GitHub App integration with the
Gemini Enterprise datastore they specify.

## Security requirements

- Never ask the user to paste a GitHub private key, webhook secret, access
  token, or Google credential into chat.
- Keep secrets in local environment variables, a protected `.env` file, or a
  deployment secret manager. Do not commit `.env` or private-key files.
- Do not create or install a GitHub App, grant permissions, expose a service
  publicly, or deploy the service without the user's explicit approval.
- Explain that the webhook validates `X-Hub-Signature-256` before processing
  events. Do not recommend disabling signature validation.
- Use the minimum GitHub App permissions needed: Issues read/write and Pull
  requests read/write. Subscribe only to issue comments and pull-request
  review comments.

## Setup workflow

1. Ask one question at a time to establish whether the user already has a
   GitHub App and a Gemini Enterprise datastore.
2. For any missing setup, explain the required GitHub App permissions/events
   and the datastore resource components. Never invent a project ID, datastore
   path, app ID, or webhook URL.
3. Help the user configure `.env` using `.env.example`. Ask them to set secret
   values locally; do not request those values in chat.
4. For local testing, guide the user to install dependencies with `uv sync`,
   authenticate to Google Cloud with Application Default Credentials, then
   start the service using `bash scripts/run_local.sh`.
5. Confirm the service health endpoint at `http://127.0.0.1:8080/healthz`.
   A GitHub webhook requires a reachable HTTPS endpoint. Explain that a secure
   tunnel or an approved deployment is needed for a local service to receive
   real GitHub events.
6. Test the webhook only after the user has configured the endpoint and
   installed the GitHub App on the intended repository. The command prefix is
   `@gemini-enterprise`; the bot ignores its own comments.
7. For code-only verification, run `uv run pytest tests/ -q`. These tests do
   not require GitHub credentials or a live datastore.

## Runtime behavior

The app processes only newly created `issue_comment` and
`pull_request_review_comment` events. It replies only when the comment begins
with the configured command prefix, defaulting to `@gemini-enterprise`. Issue
comments receive an issue-thread reply; review comments receive a reply in
their review thread. Answers are generated by the ADK agent using the configured
Gemini Enterprise datastore.

If the datastore lacks enough information, the agent should say what is
missing rather than make up internal policies or product details.
